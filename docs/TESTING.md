# Verification without production churn

`npm test` uses synthetic fixtures. The representative end-to-end test starts a loopback HTTPS simulator with a temporary self-signed certificate, launches the actual STDIO server through the official MCP client, and verifies tool discovery, read redaction, rejected extra input, preview-only behavior, default write denial, exact permit execution, replay denial, and restoration of the synthetic network. It then changes the certificate and verifies that no authenticated request reaches that peer. Temporary files are removed only after checking they remain inside the test directory.

Unit tests cover all-operation registration without execution, input/path restrictions, schema discriminator inheritance, redaction, bounded JSON, Mermaid injection, stale/expired plans, confirmation, revocation, concurrency, audit failure and ambiguous writes. Registration checks do not assert every request shape is proven against firmware. Validation tests check, on every bundled schema, that `allOf` property declarations are intersected (ACL filters, Wi-Fi RADIUS settings, DNS domain length) and that no request-body field accepts arbitrary JSON; that a `[REDACTED]` marker or `@secret:api-key` in a request body is refused before any request; and that helper tools read only the operations declared for toolset gating. The simulator also checks that `serve --no-detect` sends no router request. Write-gate tests cover plan-bound permits (only the named plan and request hash pass, malformed bindings fail closed, operation/site permits are unchanged, and end to end through the server a different previewed body is refused), not-sent failures audited as blocked while every other write failure stays uncertain, secret-field descriptions in previews, and the schema the `permit` command validates against. Hardening tests cover the privacy scan of unstaged and untracked files, the dedicated-folder rule for setup permission changes, PowerShell path and failure classification (on Windows, including a real policy-blocked run), a CA-issued certificate chain pinned to its leaf, the per-process API-key cache, fingerprint entry before display, enrollment cleanup bounds, deep-JSON limits and non-object config files. Spec-tooling tests use small synthetic specifications in `test/fixtures/specs/` and temporary directories: a synthetic 11.1.99 specification is added with one command and its change report is checked, while a specification containing an unsupported keyword (`if`/`then`) is refused by `scripts/add-spec.mjs` and fails the check.

`npm run check` verifies, for every specification in `spec/manifest.json`, that the file matches its SHA-256, passes the schema-keyword guard, compiles, and registers each operation ID exactly once with the counts the manifest records. It also fails if the manifest is not canonical, if `spec/` holds an unlisted file, or if generated documentation (`docs/OPERATIONS.md`, `docs/spec-changes/`) has drifted. `npm run verify` performs the MCP handshake and capability/resource/prompt checks against the selected local configuration, without calling the router. `npm run privacy` checks every staged file and every unstaged edit or untracked, non-ignored file (index and working-tree bytes) for prohibited artifacts and common credential formats, so it gives the same answer before and after `git add`; it cannot prove absence of every possible private detail. A separate operator review is still needed before publication.

An explicitly authorized `node scripts/verify.mjs --live` makes only a handful of read calls: version, site discovery, adopted devices, connected clients and latest device statistics. It reports counts and health without printing client labels, addresses or IDs. Never save its output into the repository. No production mutation test is included or run by CI.

To selectively test a real mutation, choose a disposable object with the operator, record its necessary recovery data privately, preview, grant a narrow short-lived permit, apply once, verify, and perform an explicitly reviewed restore if appropriate. Do not exercise restarts, deletes, bulk voucher removal, firewall ordering or connectivity changes merely to increase test coverage. Some operations are not reversible. If a write outcome is uncertain, inspect first and do not automatically retry.

CI is configured for Windows and Linux on Node 24 and 26, and runs `npm run format:check` (Prettier). A successful local Windows run does not imply hosted CI or Linux has already run; inspect the workflow result after pushing. Platform setup prompts also require a real interactive terminal and operator-verified certificate trust.
