# Contributing

Read AGENTS.md and SECURITY.md. Use synthetic network data and documentation-only identifiers. Never attach live logs, configuration, certificates, credentials, screenshots, or inventories to a change.

Install with `npm ci --ignore-scripts`. Run `npm test`, `npm run check`, `npm run privacy`, `npm run format:check`, and `npm audit`. Explain what changed, the threat model impact, and the relevant validation in the pull request. Production writes are not a required test step.

Keep dependencies pinned and review lockfile changes. For a schema upgrade, download the official vendor specification yourself, then run `node scripts/add-spec.mjs PATH --source URL` (local file only: it validates OpenAPI 3.1 and `info.version`, runs the schema-keyword guard, copies the file into `spec/`, updates `spec/manifest.json`, and writes `docs/spec-changes/<previous>-to-<new>.md`). Read that report, especially new required fields and the bold optional fields that default when omitted. Then run `node scripts/check.mjs --write`, update tests that name versions, and test representative new request shapes against a simulator before choosing any operator-approved live checks. Re-running with an identical file only refreshes reports; a different file for a bundled version needs `--replace`. `--prune` keeps the newest patch of each minor line plus the newest specification of the previous major, lists what it would delete, and asks first. If the keyword guard fails, extend `normalize()` and the allowlist in `src/catalog.mjs` together with tests; never add a keyword to the allowlist without enforcing or deliberately ignoring it. Do not silently add undocumented controller routes or generic execution tools.
